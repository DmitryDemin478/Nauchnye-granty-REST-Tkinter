# Контракт REST API — «Научные гранты» (ЛР № 3)

Базовый адрес: `http://127.0.0.1:8000`. Формат обмена — JSON.

## Гранты

| Метод и путь | Назначение | Ответы |
|---|---|---|
| `GET /api/grants` | Список грантов; необязательный `search` ищет по названию и направлению без учёта регистра. | `200` |
| `GET /api/grants/{grant_id}` | Получение гранта по ID. | `200`, `400` для нечислового ID, `404` если грант отсутствует |
| `POST /api/grants` | Добавление гранта администратором. | `201`, `400` при некорректных данных |
| `PUT /api/grants/{grant_id}` | Изменение сведений о гранте и его активности. | `200`, `400`, `404` |

## Учётные записи и исследователи

| Метод и путь | Назначение | Ответы |
|---|---|---|
| `POST /api/researchers` | Регистрация исследователя. Роль автоматически устанавливается как «Исследователь». | `201`, `400` при ошибке входных данных, `409` при занятой почте |
| `POST /api/auth/login` | Проверка электронной почты и пароля, возврат сведений об учётной записи и её роли. | `200`, `401` при неверных данных |
| `PUT /api/researchers/{user_id}/profile` | Изменение сведений исследователя. | `200`, `400`, `404` |
| `GET /api/researchers` | Просмотр списка исследователей. | `200` |

Пример регистрации:

```json
{
  "fio": "Иванов Иван Иванович",
  "specialty": "Биология",
  "degree": "Кандидат наук",
  "achievements": "Научные публикации",
  "email": "ivan@example.ru",
  "password": "1234"
}
```

## Заявки

| Метод и путь | Назначение | Ответы |
|---|---|---|
| `POST /api/applications` | Подача исследователем заявки на активный грант. | `201` с `Location`, `400` при нарушении правил, `404` если исследователь или грант не найден, `409` при повторной заявке |
| `GET /api/applications` | Просмотр заявок; необязательный `researcher_id` ограничивает список заявками одного исследователя. | `200` |
| `GET /api/applications/{application_id}` | Получение созданной заявки по ID. | `200`, `404` |
| `PUT /api/applications/{application_id}/status` | Решение администратора: `Одобрена` или `Отклонена`. Статус можно изменить только у заявки «На рассмотрении». | `200`, `400` при недопустимом статусе, `404` если заявка отсутствует или уже рассмотрена |

Пример подачи заявки:

```json
{
  "researcher_id": 2,
  "grant_id": 1
}
```

При успешном создании возвращается `201 Created`, идентификатор и статус «На рассмотрении». В заголовке `Location` указывается путь созданной заявки, например `/api/applications/1`.

## Бизнес-правила ЛР № 1

- БП-01: при регистрации обязательны ФИО, специальность и электронная почта.
- БП-02: сумма гранта должна быть больше нуля.
- БП-03: дата окончания гранта не может быть раньше даты начала.
- БП-04: заявка принимается только на активный грант.
- БП-05: специальность исследователя должна совпадать с направлением гранта.
- БП-06: повторная заявка одного исследователя на тот же грант запрещена.
- БП-07: новая заявка получает статус «На рассмотрении», после решения — «Одобрена» или «Отклонена».
- БП-08: обычная регистрация назначает роль «Исследователь»; учётная запись администратора создаётся отдельно.

## Хранение

Данные хранятся во временных словарях внутри `GrantServiceImpl`. После перезапуска добавленные данные исчезают, исходные три гранта и учётная запись администратора создаются заново.

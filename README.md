## Назначение версии

Ветка `lab-2` содержит учебную версию REST API для демонстрации двух операций получения сведений о грантах:

- `GET /api/grants` — получение списка и поиск по названию или направлению;
- `GET /api/grants/{grant_id}` — получение сведений об одном гранте.

В этой версии данные трёх демонстрационных грантов хранятся в списке `GRANTS` в `backend.py`. SQLite не создаётся и не используется. Маршруты регистрации, входа, подачи заявок, изменения профиля и административной записи в этой версии отсутствуют. Полная версия приложения с SQLite, Tkinter и заявками сохранена отдельно в ветке `full-version`.

Контракт API: [API_CONTRACT.md](API_CONTRACT.md).

## Установка

Откройте PowerShell в каталоге проекта и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
```

## Запуск API

```powershell
py -m uvicorn backend:app --reload
```

После запуска доступны:

- API: http://127.0.0.1:8000
- Документация Swagger: http://127.0.0.1:8000/docs
- Список грантов: http://127.0.0.1:8000/api/grants

## Самопроверка в PowerShell

```powershell
$url = 'http://127.0.0.1:8000/api/grants'
curl.exe -i $url
curl.exe -i -G --data-urlencode 'search=Биология' $url
curl.exe -i -G --data-urlencode 'search=Поволжья' $url
curl.exe -i -G --data-urlencode 'search=NO_MATCH' $url
curl.exe -i "$url/1"
curl.exe -i "$url/999"
curl.exe -i "$url/abc"
```

Ожидаемые статусы: `200`, `200`, `200`, `200`, `200`, `404`, `400`. Для `NO_MATCH` тело успешного ответа — пустой список `[]`.

Для проверки сохранения демонстрационных данных остановите сервер (`Ctrl+C`), запустите его снова и повторите `curl.exe -i $url`. Ответ должен совпасть с первым ответом списка, поскольку демонстрационные данные задаются в коде.

## Границы реализации

- Реализованы только два GET-маршрута грантов.
- Данные демонстрационные и находятся в памяти процесса.
- Поиск выполняется без учёта регистра по названию или направлению.
- Запись и изменение данных, авторизация, регистрация и заявки не входят в эту версию ЛР № 2.
- POST `/api/applications` описан в контракте как планируемая операция, но не реализован.
